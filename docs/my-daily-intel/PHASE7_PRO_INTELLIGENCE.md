# Phase 7 — 专业情报能力

本阶段把“我的关注”主题页从“事件聚合页”升级为“证据分层的专业情报页”。

## 已完成

- 今日最重要
- 多方验证与事件聚合
- 今日时间线
- 来源交叉验证
- 官方一手提示
- “为什么重要”
- “事实 / 已报道”
- “媒体观点”
- “系统分析”
- “对我的影响”数据结构与 UI
- 每个主题可设置“影响对象名称 / 类型”

## 证据分层原则

### 事实 / 已报道
只展示具体报道标题、来源和 AIHOT 已有事件数据。

### 媒体观点
当前 AIHOT 数据没有把“媒体观点”单独结构化时，不把标题、摘要或系统分析伪装成媒体立场，明确显示“暂无结构化观点”。

### 系统分析
优先使用 AIHOT 已有 story digest / summary，其次使用原有推荐理由；始终明确标注为“系统分析”。

### 为什么重要
第一版只使用可解释信息组成：
- 与用户规则的匹配原因
- 相关度
- 多源交叉报道
- 是否含官方一手

不自动加入未经数据支持的因果判断。

## 来源交叉验证

story 级事件使用 AIHOT 原生：
- sourceCount
- reportCount
- officialReports

fact 级内容调用原有 group reports 接口，按来源名称去重计算来源数量。

展示口径：
- 有官方一手 + 多源交叉
- N 个来源交叉报道
- 单一来源 / 暂未交叉验证

不对媒体给出绝对“真假分”。

## 对我的影响

本阶段先建立数据结构与 UI，不自动判断利好 / 利空。

每个关注主题可本地设置：
- 影响对象名称
- 影响对象类型：主题 / 资产 / 基金 / 股票 / 公司 / 人物 / 国家 / 行业 / 其他

情报卡当前默认：
- 状态：待观察
- 说明：已确认与关注规则相关，但未接入因果分析，不自动判断方向

后续可在此结构上接模型分析或人工判断。

## 隐私

关键词、排除词、专家规则、权重、影响对象均只保存在浏览器 localStorage，并随个人配置 JSON 导出/导入。

服务端只读取 AIHOT 自己已有的公开 fact/story/source 数据，不接收个人关注配置。

## 保持不变

- 原 AIHOT 精选 / 全部
- 热点榜
- story 事件页
- 日报 / 周报 / 月报
- 公共专题
- 搜索与筛选
- 收藏与已读
- PC / 移动端 UI 体系
