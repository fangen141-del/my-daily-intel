# Phase 8 — 最终 UI/UX 与功能完整性审计

本阶段同时审计两类问题：

1. 与原 AIHOT 相比是否发生 UI/UX 退化。
2. 用户要求的功能是否真正工作，而不是只有配置字段或静态 UI。

## 一、母版完整性结论

从最初 AIHOT 基线 commit `04978ba...` 到当前产品，原核心 UI 文件几乎没有被重写。

原版以下核心能力仍保持：
- 精选 / 全部动态
- 搜索、筛选、频道、类别、标签
- 热点榜
- fact / group / story 事件体系
- 日报 / 周报 / 月报
- 公共主题
- 收藏与已读
- 阅读详情
- 桌面 Sidebar
- 手机 TabBar
- 亮 / 暗主题
- 960px 响应式壳层
- View Transition / 移动端返回动效
- worker / publication / API / Docker / CI

个人能力主要集中在 `modules/personal-intel/`，没有另起炉灶重写 AIHOT。

## 二、本轮发现并修复的 UI 退化

### 1. 首页手机端顺序退化 — 已修复

问题：
“我的重点关注”最初挂在 root Top，手机端会出现在 AIHOT 原版 FeedBar 之前。

修复：
新增 home-only 模块插槽 `homeTop`，把“我的重点关注”放到：
- FeedBar
- ActiveFilters

之后，热点和时间线之前。

结果：
保留原版手机顶部操作节奏，同时仍满足“我的重点关注先于普通热点”。

### 2. 新增页面缺少原版 PhoneBar — 已修复

问题：
我的关注 / 管理 / 专家模式 / 主题情报页面在手机端没有 AIHOT 原生顶部栏。

修复：
对四个页面统一接入原版 `PhoneBar`，并保持桌面端原有标题结构。

## 四、Phase 8 不允许“假完成”

以下项目在真正接线以前不得标记为完成：

- 来源类型筛选
- 刷新频率
- 对象关注的一等数据模型
- 编辑首页
- 媒体 / 市场观点结构化栏目
- 社交媒体讨论栏目

## 五、下一步修复顺序

1. 让刷新频率真正控制主题情报页的自动重读。
2. 建立对象类型（公司 / 人物 / 资产 / 国家 / 行业等）为关注主题的一等字段，而不是只作为影响对象。
3. 增加首页编辑能力，但只在 AIHOT 原信息架构允许的范围内调整，不改成 Dashboard。
4. 为来源增加可公开的类型元数据，再让来源筛选真正生效。
5. 将 news / X / official 等现有数据分成媒体报道、官方消息、社交讨论；观点栏目只在结构化数据存在时显示。
